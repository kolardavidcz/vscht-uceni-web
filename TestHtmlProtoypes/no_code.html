🎨 Options for Non-Coding Topics (No Code Styles)

10 examples showing different visual styles and terminology for conceptual or non-implementation materials.

01
NO CODE (Fuchsia Tinted Card)
Soft purple-pink tinted background with a light pastel badge. Feels modern and developer-friendly.
NO CODE Specifikátor noexcept
02
THEORY (Dashed / Conceptual Outline)
Dashed borders with a slate-gray badge. Explicitly shows the item has a "different/conceptual" structure.
THEORY Složitost algoritmů
03
CONCEPT (Indigo Solid Badge)
Indigo badge with tinted blue-ish outline. Focuses on mental models and learning programming concepts.
CONCEPT Move sémantika
04
SYNTAX (Outline Style)
Uses a clean outlined badge. Represents language syntax rules that you just write down, not complex logic.
SYNTAX Klíčové slovo using
05
DESIGN (Amber OOP Badge)
Gold/amber gradient, used for OOP design relationships (UML, class design, interfaces) rather than syntax.
DESIGN Vztahy mezi třídami
06
LOGIC (Rose-Red Badge)
For pure logical reasoning and mathematical proofs (e.g. proof of BST search time complexity).
LOGIC Důkaz složitosti BST
07
ALGORITHM (Teal Gradient)
For high-level algorithmic processes that you understand theoretically (e.g. how Dijkstra operates).
ALGORITHM Fungování BFS
08
TOOL (CLI / Tech Look)
Monospace look, slate dark background. Represents configuration, compiling, or command line usage.
TOOL Kompilace g++
09
READ ONLY (Muted Warning style)
Clear instruction tag that the topic is read-only information, not active coding material.
READ ONLY Programátorský styl
10
BEST PRACTICE (Green Gradient)
For C++ best practices, guidelines, and clean code standards.
PRACTICE Pojmenování proměnných
